Overview

GreenDial is a personal health platform powered by Doc, a primary AI coordinator, and a team of specialist health agents. Doc guides conversations, builds the user's health profile, and routes domain-specific questions to the right agent. When a message matches two or more agent domains, Cross AI synthesizes perspectives from multiple specialists in parallel.

Agents also run on a server-side cron schedule (08:00 UTC daily), generating personalized check-in notifications for subscribed users. Each agent has its own dedicated chat tab in the UI, with a profile-building onboarding interview on first activation.

Authentication is username + passphrase for the app; HTTP Basic Auth for third-party integrations.

How agents activate

1. Via Doc (chat-triggered) — Doc checks keyword lists and emits **CALL_AGENT**. Single-domain → specialist. Two or more domains → Cross AI runs matched agents in parallel threads and synthesizes.

2. Via agent direct chat — Users open an agent's tab; the server routes to POST /chat/agent/{agent_id}. Each agent maintains its own transcript separate from Doc.

3. Via crontab (scheduled) — agent_runner.py at 08:00 UTC daily. Per-user, per-agent, 20-hour debounce. Results land in the notification bell.

All agents are kind, helpful, and truthful — expert systems backed by scientific and medical LLMs. The Mental Wellness Guide provides the 988 crisis line for users expressing suicidal ideation.

Agents

There's no subscription API to manage — every user gets daily check-ins from all specialist agents automatically once notifications are enabled (see notifications_enabled under Settings above). Doc still routes conversations to the right specialist (or several, via Cross AI) behind the scenes; specialists also each have a dedicated chat tab. First activation of a tab triggers a 3-turn onboarding interview that fills domain-specific profile fields.

Cron runner: agent_runner.py — 08:00 UTC daily, 20-hour debounce per user per agent (weekly for protect and cross_ai, via each agent's CRON_CADENCE_HOURS). Logs to /var/log/greendial_agents.log. Manual run:
python3 agent_runner.py --agent protect --user user_alice --dry-run

Suggestions, Activities & Universal Bounty (UB) API Demand-Side

Each day GreenDial generates up to 3 personalized Suggestions per user (exercise, diet, social) — separate from the notification bell. A Suggestion becomes an Activity when accepted. UB-backed suggestions (see below) are surfaced first, ahead of LLM-generated ones. See About & FAQ for the plain-language explanation of Universal Bounty.

Suggestions

GET /suggestions/{user_id}
Return the user's current suggestion batch.
POST /suggestions/{user_id}/generate
Generate a new batch (cron or on-demand). Respects a 24h cadence unless forced.
POST /suggestions/{user_id}/generate {"force": false}
POST /suggestions/{user_id}/{suggestion_id}/accept
Accept a suggestion → creates an Activity with status: "active".
POST /suggestions/{user_id}/{suggestion_id}/dismiss
Dismiss a suggestion without creating an Activity.

Activities

GET /activities/{user_id}
List the user's activities (active, completed, and abandoned).
PATCH /activities/{user_id}/{activity_id}
Mark an activity completed or abandoned.
PATCH /activities/{user_id}/{activity_id} {"status": "completed"}
On "completed": sets completed_at, snapshots the user's linked wallet address into wallet_snapshot, and — if the activity has a price — sets payment_pending: true. On "abandoned": only valid from "active"; sets abandoned_at.

Bounties Demand-side

Anyone can sponsor a Universal Bounty — friends and family (signed-in session on /sponsor), or insurers, employers, and government programs with X-API-Key: <DEMAND_API_KEY>. A UB targets an explicit list of user_ids; matching users see it as a priced Suggestion. Supports recurrence: once | weekly | monthly.

Demand-side account model

  • Friends/family: normal GreenDial login + X-Session-Token (or the Sponsor UI). No demand API key required.
  • Institutions: demand-side API key; create/list/delete UBs and call /generate for previews.
  • Recipients: opt into public discovery under Settings → Universal Bounty (default off). Directory: GET /bounty/directory.
  • Drafting: POST /bounty/autocomplete (public) returns chips, activity text, and suggested price. Default: “Take a walk sometime in the next day”.

Quick start: sponsor an activity end-to-end

A minimal integration for a new demand-side sponsor — or use /sponsor in the browser.

# 0. Autocomplete a draft (no key) — chips + suggested price curl -X POST https://greendial.org/bounty/autocomplete \ -H "Content-Type: application/json" \ -d '{"description": "walk", "enrich": true}' # 0b. Discover opt-in recipients curl "https://greendial.org/bounty/directory?q=" # 1. Preview a UB payload for a user curl -X POST https://greendial.org/generate \ -H "X-API-Key: $DEMAND_API_KEY" -H "Content-Type: application/json" \ -d '{"user_id": "user_abc", "description": "walk", "recurrence": "weekly"}' # 2. Create the UB — once or subscription-style curl -X POST https://greendial.org/bounty \ -H "X-API-Key: $DEMAND_API_KEY" -H "Content-Type: application/json" \ -d '{"activity": "Take a walk sometime in the next day", "health_area": "exercise", "price": 5.00, "currency": "USD", "user_ids": ["user_abc"], "recurrence": "once", "expires": "2026-12-01"}' # 3. Check later curl https://greendial.org/bounty/bty_a1b2c3d4e5f6 \ -H "X-API-Key: $DEMAND_API_KEY" # 4. Delete when done curl -X DELETE https://greendial.org/bounty/bty_a1b2c3d4e5f6 \ -H "X-API-Key: $DEMAND_API_KEY"

Don't have a key yet? See the FAQ for how to request one. Remember: UB is honor-system payment, not on-chain escrow — see the note below.

How Doc Works

Doc is the primary coordinator. Its prompt is assembled dynamically each turn from profile state, conversation stage, and optional agent context.

Two structured markers are stripped server-side before returning text to the user:
• **PROFILE_UPDATE** {"field": "value"} — persists health data
• **CALL_AGENT** {"agent": "sleep"} — triggers a specialist sub-call

Dispatch flow

User message │ ├─ keyword match → 0 agents → Doc answers directly │ ├─ keyword match → 1 agent → specialist runs → Doc synthesizes with context │ └─ keyword match → 2+ agents → Cross AI runs matched agents in parallel threads → Cross AI synthesizes → Doc wraps final reply Profile updates extracted from any response → saved to S3 → sidebar refreshes

Language mirroring

All agents (Doc and specialists) detect message length and tone from each user turn and inject a style-matching instruction. Very short messages get terse replies; detailed messages get thorough ones. Casual phrasing gets casual responses.

Profile update syntax

// Set a field **PROFILE_UPDATE** {"age": "44", "health_conditions": "type 2 diabetes"} // Append to existing value **PROFILE_UPDATE** {"medications": "+metformin 500mg twice daily"} // Delete a field **PROFILE_UPDATE** {"allergies": null} // Nested sub-object **PROFILE_UPDATE** {"vitals": {"bp": "120/80", "resting_hr": "62"}}
