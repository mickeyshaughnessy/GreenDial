# GreenDial Mobile & App Readiness

Status of the mobile-optimization work and a prioritized path to a native app.
Written 2026-06-25.

---

## 1. What shipped (this round)

### Responsive web (Area 2)
- Real mobile media queries in `index.html` (`max-width: 700px` / `420px`):
  header wraps with horizontally-scrolling nav tabs, `100dvh` heights (fixes
  mobile browser-chrome gaps), responsive notification dropdown (was a fixed
  360px that overflowed phones), and tighter padding.
- **16px form inputs on mobile** — stops iOS Safari from auto-zooming on focus.
- `viewport-fit=cover` + `env(safe-area-inset-*)` padding for notched devices.

### Sticker board (Area 2)
- Topic-label column is **frozen** (`position: sticky; left: 0`) in both the
  in-app board (`index.html`) and the public shared board (`stickers.html`).
- Board **auto-scrolls to today** on load, so the most relevant column is in
  view without horizontal scrolling. Older days scroll off to the left.

### Installable PWA (Area 3)
- `manifest.json` (standalone display, theme color, categories, icons).
- `sw.js` service worker: offline app-shell cache (network-first navigations,
  cache-first static assets, API requests pass straight through).
- App icons generated by `generate_icons.py` (`icons/icon-192.png`,
  `icon-512.png`, `icon-512-maskable.png`).
- iOS/Android meta tags + `apple-touch-icon` in `index.html`.
- Flask serves the assets in dev; `deploy.sh` copies them to the nginx webroot
  for prod (`/var/www/greendial/`).

### Web push groundwork (Area 3)
- `push.py` — VAPID send helper (`send_to_user`, prunes dead subscriptions).
  Degrades to a safe no-op if `pywebpush` or VAPID keys are absent.
- Endpoints: `GET /push/vapid-public-key`, `POST /push/subscribe/<user_id>`,
  `POST /push/unsubscribe/<user_id>` (session-token protected).
- Subscriptions stored on the user record under `push_subscriptions` (capped 10).
- Client: SW registration + `maybeSubscribePush()` + public
  `enablePushNotifications()` hook in `index.html`.
- `sw.js` push + notificationclick handlers (focus/open the app).
- `push_reminders.py` — daily check-in reminder sender, intended for cron.
- VAPID keypair generated and stored in `config.py` (gitignored, synced by
  `deploy.sh`). Public key is exposed to browsers via the endpoint above.

## 2. Push is LIVE in prod ✅

All wiring is done — users can opt in from **Settings → Notifications → Push
reminders** (Chrome/Android/desktop today; iOS once installed to Home Screen).

- `pywebpush==2.0.0` installed in the prod venv (`/root/GreenDial/venv`);
  `push.push_configured()` returns `True`.
- `VAPID_*` keys live in the server's `config.py` (synced by `deploy.sh`).
- Daily reminder cron on the prod VM (alongside the 08:00 agent runner):
  ```
  0 15 * * *  /root/GreenDial/venv/bin/python /root/GreenDial/push_reminders.py >> /var/log/greendial_reminders.log 2>&1
  ```
  (15:00 UTC ≈ 10am ET / 7am PT — adjust to taste.)
- Settings toggle calls `togglePush()` → `enablePushNotifications()` /
  `disablePushNotifications()`. We still do **not** prompt for permission on
  page load by design; users opt in explicitly.

> Note: iOS only delivers web push to PWAs **installed to the Home Screen**
> (iOS 16.4+). Android/desktop Chrome work from the browser tab.

## 3. Android Capacitor shell ✅ (in repo)

The Android app lives under `mobile/` — a Capacitor WebView that loads
`https://greendial.org` (app ID `org.greendial.app`). Build and Play Console
steps: **`mobile/README.md`**.

- Privacy policy URL for Play: **https://greendial.org/privacy** (`privacy.html` + `/privacy` route).
- Release AAB: `cd mobile && npm run bundle` → `android/app/build/outputs/bundle/release/app-release.aab`.
- Upload keystore is local-only (`mobile/android/keystore/`, gitignored) — back it up.

Ship path: Play Console → **Internal testing** with the AAB → tester opt-in on phone → promote to production when ready.

Ranked by leverage.

| # | Gap | Why it matters | Effort |
|---|-----|----------------|--------|

| 3 | **Play production listing polish** | Screenshots, feature graphic, Data safety, content rating, production track. | S |
| 4 | **Native push (APNs/FCM)** | iOS web push is install-gated; WebView push may be flaky vs FCM. | M |
| 5 | **iOS / App Store** | Separate Capacitor iOS target + Apple Developer account. | M |
| 6 | **Health integrations** | Apple Health / Google Fit / wearables auto-fill the sticker board. | L |
| 7 | **Offline write queue** | Today the SW only caches the shell; check-ins/chat fail offline. | M |
| 8 | **Passphrase hashing** | Plaintext passphrases are an app-store review and trust risk. bcrypt + migration. | M |
| 9 | **Deep links / universal links** | `/stickers/<token>` and chat should open the app, not the browser. | S |

### Notes / corrections to earlier assumptions
- **Sessions are persisted**, not purely in-memory: the session token lives on
  the S3 user record (`session_token`), so login survives server restarts. The
  in-memory `_sessions` dict is only a cache. No change needed for app login
  persistence beyond storing the token client-side (already done in
  `localStorage`).

## 5. Landing-flow notes (Area 1)

Decision this round: **keep the shared board (`stickers.html`) minimal** — no
signup CTA added. It remains the highest-leverage growth surface if we later
want to add a "Start your own board" hook; the table is now mobile-friendly
(frozen labels + auto-scroll) so it presents well when shared to a phone.

The retention loop is: **daily emoji check-in → fills the sticker board →
visible streak → shareable link.** Push reminders (above) are the "come back"
trigger; making the board the first thing a returning mobile user sees would
strengthen it (future consideration).
